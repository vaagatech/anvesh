Distributed Architecture

How Anvesh distributes data, coordinates nodes, and ensures fault tolerance across the cluster.

System Overview

Anvesh follows a shared-nothing architecture. Each node independently handles queries for the shards it owns. The Hub component acts as the coordination layer and entry point.

Data Distribution

Indexes are split into shards distributed across available Anvesh Engine nodes. Each shard contains:

  • Inverted index — BM25 tokenized term postings
  • HNSW graph — dense vector approximate nearest neighbor index
  • Column store — stored fields for retrieval and faceting
  • WAL — write-ahead log for crash recovery

Segment Lifecycle

Documents are written to an in-memory buffer, then flushed to immutable segments. Small segments are periodically merged. Stale segments are promoted to object storage automatically.

  1. Buffer → documents held in memory + WAL
  2. Flush → immutable segment written to disk
  3. Merge → small segments consolidated into larger ones
  4. Tier → cold segments offloaded to S3/OCI Object Storage

Fault Tolerance

  • Replica shards — configurable replication factor per index
  • Write-ahead log — survives process crashes
  • Dead-letter queue — captures and retries failed operations
  • Health checks — Hub detects unresponsive nodes and re-routes queries
Single-node mode: For development and small deployments, Anvesh runs as a single process with all components embedded. No external dependencies needed.
