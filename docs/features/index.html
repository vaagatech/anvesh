Features & Capabilities

Full-text BM25, dense vector retrieval, hybrid rank fusion, geo-indexing, dead-letter reliability, and tiered object storage.

Hybrid Search Engine

Anvesh combines BM25 full-text scoring with dense vector similarity search using Reciprocal Rank Fusion (RRF). A single query returns results that are both lexically and semantically relevant — no separate systems required.

  • BM25 Full-Text — inverted index with configurable tokenizers, stemming, and stop-word filters
  • Dense Vector (HNSW) — approximate nearest neighbor using hierarchical navigable small world graphs
  • Hybrid mode — fuse both signals via RRF with configurable alpha weighting

Tiered Object Storage

Anvesh automatically tiers data between fast local NVMe and cheap object storage:

  • Hot tier — NVMe/SSD for frequently accessed segments
  • Warm tier — S3, OCI Object Storage, or MinIO for infrequently accessed data
  • Automatic promotion — segments are pulled to hot tier on query demand
Cost impact: Tiered storage alone can reduce infrastructure costs by 60–70% compared to keeping all data on hot storage.

Dead-Letter Queue (DLQ)

Every failed indexing operation is captured in a durable Dead-Letter Queue. The DLQ provides:

  • Automatic retry with exponential backoff
  • Manual inspection and replay via the Hub UI
  • Metrics and alerting on DLQ depth
  • Zero-document-loss guarantee

Geo-Spatial Search

Native geo-point indexing with support for:

  • Radius queries (within N km of a point)
  • Bounding-box filters
  • Polygon containment checks
  • Sort by distance

Real-Time Aggregations

Built-in aggregation framework that runs at query time:

  • Terms — top-K value counts
  • Histogram — numeric bucket distributions
  • Date ranges — temporal groupings
  • Nested facets — multi-level drill-down
