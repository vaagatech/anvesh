Features & Technical Capabilities

Comprehensive feature guide of the Anvesh search and vector intelligence suite.

1. Hybrid Full-Text & Dense Vector Search

Anvesh bridges the gap between lexical precision and semantic comprehension:

  • BM25 Okapi Algorithm: Configurable k1 and b parameters for term frequency saturation and document length normalization.
  • Dense Vector Embeddings: Native cosine, dot product, and Euclidean vector distance over custom dimensional embeddings (e.g. 384, 768, 1536-dim).
  • Reciprocal Rank Fusion (RRF): Smoothly fuses keyword rankings with vector similarity ranks to surface the most relevant answers without manual weight calibration.

2. Universal Dead-Letter Queue & In-UI Replay

Zero data loss during streaming ingestion or web crawling:

  • Failure Isolation: If a document has bad encodings, invalid schema types, or crawler network errors, it is logged to daily append-only JSONL files (/data/dead-letter/*.jsonl).
  • Ring Buffer Querying: Instant in-memory retrieval of the last 500 failed entries via GET /v1/dead-letter and GET /hub/dead-letter.
  • 1-Click Replay in Hub UI: Operators can review formatted JSON payloads, inspect error traces, and click ⚡ Replay Single Record or ⚡ Replay All to re-ingest.

3. Adaptive ResourceGuard (≤ 75% Memory Ceiling)

Proactive memory management tailored for high-concurrency Node.js environments:

  • Gradient Micro-Pacing: Rather than aborting operations when memory rises, Anvesh introduces 5ms–35ms micro-delays between stream chunk processing to let V8 Scavenger and Mark-Sweep GC reclaim heap gracefully.
  • Adaptive Chunk Sizing: Dynamically scales ingestion batch sizes based on document byte payloads (>50KB to 1MB+).

4. Multi-Cloud Tiered Storage (RAM → NVMe → S3 / OCI)

  • Hot Tier: In-memory inverted index and vector arrays for sub-millisecond querying.
  • Warm Tier: Local NVMe disk snapshots for instant node reboot recovery.
  • Cold Tier: Pluggable AWS S3 or OCI Object Storage bucket backups for 90% cheaper long-term retention.

5. Native Wire-Compatible Search Adapters

Route existing Elasticsearch and Solr HTTP traffic directly into Anvesh with zero client code modifications:

# Elasticsearch wire compatibility
POST /_search
{
  "query": { "match": { "title": "cloud native search" } }
}
