Enterprise Architecture Pillars

Engineered for Unmatched Reliability & Efficiency

Built from scratch to eliminate the technical debt and maintenance headaches of legacy search engines.

🚀

Sub-100MB JVM-Free Footprint

Zero Java memory overhead, zero JVM heap tuning, and no stop-the-world garbage collection pauses. Anvesh microservices run on tiny K3s containers with sub-100MB RAM.

🛡️

Universal Dead-Letter Queue & Replay

Single bad records never abort streaming ingestion batches. Failures are cleanly isolated to daily append-only JSONL files with interactive single-record and batch replay in the Hub UI.

⚖️

Adaptive ResourceGuard (≤ 75% Limit)

Monitors system pressure in real-time. In-flight operations dynamically receive graduated non-blocking micro-delays (5ms–35ms) to guarantee smooth execution without abrupt task drops.

💾

Tiered S3 & OCI Object Storage

Hot index shards reside in memory, warm shards on fast local NVMe SSDs, and cold historical indices automatically spill to low-cost AWS S3 or OCI Object Storage for 90% storage savings.

🔄

Elasticsearch & Solr Wire Adapters

Drop-in replacement for existing software. Route your existing Elasticsearch /index/_search and Solr /solr/select HTTP API traffic directly into Anvesh without changing frontend code.

📊

Full Prometheus & OpenTelemetry

Standardized /metrics across Engine (:3848), Spider (:3851), Indexer (:3852), and Hub (:3849). Dedicated Kubernetes Prometheus pod manifest included out of the box.

Deploy in 60 Seconds

Run Anvesh locally, in Docker, or on your Kubernetes cluster with a single command. All microservices automatically wire together through the Hub control plane.

# 1. Run local Anvesh standalone cluster
